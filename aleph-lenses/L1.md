# LENS 1 - TSP TOOLS

**The question: what do the studio's own gates say, run literally?**

This lens is not a reading. It is the arithmetic. You run the scripts and report what
they return. Where the other four lenses interpret, this one measures.

## What to run

From the hub, against the surface:

```
python3 comfort-gate.py --ratchet --repo=<REPO> <file>      # contrast/dark/offline/emoji, 390x844
python3 preship-gate-v4.py --ratchet --repo=<REPO> <file>   # tokens, type floor, image floor, dark promise
python3 one-thing-gate.py --ratchet --repo=<REPO> <file>    # entry paint, phone-binding + laptop
python3 studio-voice-gate.py --ratchet --repo=<REPO> <file> # founder voice
python3 studio-eyes-sweep.py <file>                         # render-proof, WeasyPrint
python3 playthrough-agent.py <file>                         # dead controls, JS errors, dead ends
python3 studio-eyes/studio-fingers.py <file>                # touch
bash studio-belt.sh .                                       # all five ticks at once
```

The belt is the short version: five ticks, ratcheted, one command.

## The rule that makes this lens honest

**A gate that cannot run HALTS. It never reports clean.**

This is not a style note - it is the studio's most expensive lesson. The render-proof
gate silently rubber-stamped every push for weeks because WeasyPrint was uninstalled,
the sweep exited 2, and the ratchet read "no halts" as "all clean". If a tool errors,
is missing a dependency, or exits 2, report that as `evidence` and do NOT list its keys
in `passed`. An audit that cannot see does not certify.

## `passed` is the load-bearing field

List every floor key you actually ran a check for and found clean. This is what lets
the synthesis tell "L1 looked and it was fine" apart from "L1 never looked" - and the
second one is how blind spots hide. If you did not run a check, do not list its key.

## Keys you may report

All of them, but you own `floor`. When another lens later names a floor key you did not,
the harness records a **tool blind spot** against the gate, not against you - the tool
is what gets hardened. Two live examples of exactly that:

- comfort-gate missed a dark-on-dark heading because `--brass-fill` is a *fill* token and
  the gate only samples text tokens (2026-08-03).
- studio-eyes-sweep does not contrast-check text inside an `<svg>` viewBox, so a 3.79:1
  label sat on the studio's own front page unflagged until it was moved to HTML (2026-08-07).

Both were found by eye, not by gate. That is the hole this lens exists inside.

## Output contract

Return the JSON in `aleph-fleet.py --schema`. Put the actual measured number in
`evidence` - "3.79:1 on --cool-fill", "11.3px at 330px width", "77 words before first
action at 390px". A floor finding without its number is a claim, not a measurement.
