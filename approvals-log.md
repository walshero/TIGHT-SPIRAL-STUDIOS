# APPROVALS LOG: student work published or linked by the studio

Opened 2026-08-09. Required by `student-attribution-standard.md` clause 1, which has said
since 2026-08-03 that a student email granting permission must be recorded here, and that a
missing approval line is a HALT. The clause existed. The log did not. This is it.

## WHAT THIS FILE MUST NEVER CONTAIN

This repo is public. So the log records that consent exists and where it lives. It does not
reproduce it.

- **No email address.** Not the student's, not a forwarded header, not a quoted signature.
- **No full surname.** First name plus last initial, the same form the published credit uses.
  A log that carries the surname would undo the standard it enforces.
- **No section number, no term-year on a course line.** Same rule as the credit itself.
- **No quoted body text from the student's message.** The fact of permission is the record.
  The wording is private correspondence and stays in the mailbox.

Anyone who needs the original message asks Matt, who holds it. The point of a log is that a
gate can read it without anybody reading the student's mail.

## FORMAT (from the standard, clause 1)

Student first name and last initial, game title, the words "email approval on file", and the
date recorded. One entry per published or linked student work.
